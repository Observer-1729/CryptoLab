01 / FOUNDATIONS

Encoding vs Encryption vs Hashing

These three operations can all transform data into a different-looking representation, but they solve different problems.

EncodingChanges representation so data can be stored or transported. It is reversible and uses no secret key. Example: Base64.
EncryptionProtects confidentiality by transforming plaintext with a key. Decryption requires the appropriate key. Example: AES.
HashingCreates a fixed-length digest intended to be one-way. It is useful for integrity checks and other security designs. Example: SHA-256.
02 / CLASSICAL CRYPTOGRAPHY

Classical vs modern cryptography

Classical ciphers generally manipulate letters using simple substitutions or rearrangements. They are useful for learning core ideas, but their small key spaces and recognizable patterns make them insecure.

Modern cryptography uses rigorously analyzed algorithms, larger key spaces and carefully designed protocols. Real systems also depend on secure key management, implementation and randomness.

03 / ENCODING

Why Base64 is not encryption

Base64 maps bytes to a limited set of printable characters. Anyone can decode it without a password or secret key. It is an encoding format, not a security boundary.

04 / SUBSTITUTION CIPHERS

Caesar and Vigenère ciphers

Caesar: shifts each letter by a fixed number of positions in the alphabet. A shift of 3 maps A to D. There are only 25 non-zero shifts, so brute force is trivial.

Vigenère: uses a repeating keyword to determine a different shift for each letter. It is more complex than Caesar, but repeating-key patterns and statistical analysis make it unsuitable for real security.

05 / HASHING

What SHA-256 does

SHA-256 is a member of the SHA-2 hash family. It accepts input of arbitrary length and produces a 256-bit (32-byte) digest, commonly shown as 64 hexadecimal characters. A hash is not decrypted; changing the input changes the digest. SHA-256 alone is not a password-storage scheme — use a password-hashing function such as Argon2id, scrypt or PBKDF2 with salts for that purpose.

06 / USE RESPONSIBLY

Security disclaimer

CryptoLab is an educational toolkit. Caesar, ROT13, Vigenère and simple encodings do not provide meaningful protection. Do not use these tools to protect passwords, personal information, financial data or confidential communications. For real applications, use vetted, modern cryptographic libraries and protocols.
